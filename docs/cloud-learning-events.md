# 学习事件、证据与申报用时

每个学生拥有独立、递增的事件游标。作答、课程或阅读完成、经济投影变化和时间检查点按事务追加；历史成绩固定引用题目及规则版本。客户端不能上传一份正确率或余额覆盖这些记录。

## 阅读、故事与数感

听读和跟读通过 `POST /students/{id}/learning-sessions` 创建 `kind=reading` 会话，同时给出精确教材/课文来源及 `reading_kind=listen|followup`。会话固定内容版本，可以没有题目；完成仍调用该会话的 `/complete`。不同阅读会话的重复完成会留活动记录，但同一规范阅读键只奖励一次，听读与跟读分别按原规则记 5/10 XP。故事成绩来自服务端逐题判分，首次奖励根据达标情况为 15 或 5 XP，重读不重新发奖。

摘要区分阅读完成次数与去重后的篇目/活动类型数；故事保留历次成绩，提供最好成绩、最近成绩及完成次数。一次作答或阅读不被解释为统一知识点“已掌握”。

数感练习的无提示首答、独立与迁移题目数量由固定题目版本、首答记录及服务端提示记录计算。初始 DTO 不包含全部提示；学生明确请求 `/learning-sessions/{id}/hint` 后逐条下发并记录，后续提交 `hint_level=0` 不能消除已使用的提示。客户端申报更高提示级别只会使证据更保守，不能增加无提示正确数。

数感隔天检验先验证已有练习和到期日期，服务端选择原日期变体，检验不提供提示。完成时再次校验是否到期，两台设备同一天完成仅一次更新有效检验和奖励；错过一次响应用原操作标识重试。练习日不直接标成“隔天仍会”，通过后按原规则安排 7 天后的复习，否则次日再练。

## 时间检查点

孩子模式可向 `POST /students/{id}/events` 提交：

```json
{
  "kind": "time_checkpoint",
  "session_id": "<学习会话 UUID>",
  "activity_id": "<本次前台计时 UUID>",
  "sequence": 1,
  "client_at": "2026-11-01T12:01:00+08:00",
  "started_at": "2026-11-01T12:00:00+08:00",
  "ended_at": "2026-11-01T12:01:00+08:00"
}
```

继续使用 Cookie、Origin、CSRF 与 `Idempotency-Key`。时间区间必须带时区，单个检查点不超过 30 分钟，不能超出会话开始或服务器时间允许的 5 分钟偏差。计时活动绑定一个学生及会话，不能换身份或来源；已结束会话拒绝后续新时段，允许受约束的延迟检查点。

客户端请求标识与“活动 UUID + 序号”分别去重：更换请求标识重放相同检查点也不会追加事件，相同序号改动区间返回 409。原区间、客户端声明时间和数据库接收时间都保留。退出、撤销或归档后的提交仍须通过当前权限，不能借待同步数据恢复写权限。

**这些是申报用时，不能证明实际专注度。** 用时不直接兑换 XP 或宝石。两个设备、标签页或活动的重叠区间按学生合并，只计算一次；再按家庭时区跨日拆分，以周一作为周界。计算使用 UTC 实际经过时间，因此夏令时重复小时不会被当成零分钟。

## 汇总重建

`GET /students/{id}/summary` 从追加事件重建每日活动、故事表现、去重阅读、数感证据及经济投影；`projection_matches` 用于核对存储投影和重算结果。学习端仅能读取自己；最近验证的家长可读本家庭学生，管理员不能通过建号权限读这些明细。

经济事件包含版本化规则与稀疏状态变化，能重建当时已经确认的投影，不对历史作答重新判分，也不按新规则重新发奖。统计包含客户端声明时间及服务端时间；首次奖励及其日期以服务端结算为准，用时按申报区间展示，不能混称为服务端测得的专注时间。
