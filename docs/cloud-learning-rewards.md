# 服务端学习奖励与账本

经济规则版本为 `cstf-economy-1`。数值、30 件装扮、16 项成就和 10 条每日任务定义从现有 core 导出，带来源文件 SHA-256；更新定义后在仓库根目录运行：

```sh
node --import tsx scripts/cloud/export-learning-policy.mts
```

导出文件是 `apps/api/app/learning/policy.json`，不含题目或答案。Python 经济纯函数使用原 `packages/core/spec/golden-vectors.json` 对照，SRS 间隔、跳级抽样及判分另有共用向量。云端客户端不得再直接调用原本地 store 的发奖方法。

## 权威结算

`POST /api/v1/learning-sessions/{id}/complete` 接收 `revision`、带时区的 `client_at`，并使用 `Idempotency-Key`。服务端从已记录首答计算成绩，不接受客户端 XP、宝石或正确数。普通课、挑战、复习、故事、听读、跟读、跳级和数感使用各自原有规则；跳级本身不发课程 XP/宝石，正常成就仍独立按服务器进度检查。

课程沿用首答计分、三星阈值、少于三题的微练习、首次三星、周末和挑战倍数、每日目标、最好成绩、宝箱及连胜。复习回炉不重复推进 SRS，允许已完成部分的复习通过 `abandon=true` 结束并结算首答；其他入口不能用此参数绕过未完成题目。阅读规范键只奖励一次，重复活动仍保留事件。数感检验在开始与结束分别验证到期状态，不能通过并行会话重复领取。

数据库事务把学生范围内的作答/结算、事件、余额投影、唯一领取记录和幂等回执一起提交。学生行锁串行化并发写入；相同键相同请求返回原响应，同键异体返回 409。已经结算的会话换键重放也只返回已有结算，不再发奖。

`reward_ledger` 保存规则版本、来源操作、XP/宝石增减和稀疏投影变化，`reward_claims` 对学生及一次性领取键建立唯一约束。账本和领取记录禁止 UPDATE；隐私删除可按学生级联清理。不会把整份客户端存档或客户端余额作为权威状态。

## 任务与商店

`POST /api/v1/students/{id}/economy/actions` 接收 `kind`、`client_at` 与该操作专用字段，继续要求 Cookie、Origin、CSRF 及 UUID 幂等键：

| kind | 专用字段与检查 |
| --- | --- |
| `daily_reward` | 按服务端有效连胜取表，每日一次 |
| `quest` | `quest_id`；验证当日确定性任务及服务端进度，不接收奖励数额 |
| `chest` | `book_id`、`chest_id`；由真实教材课时顺序验证解锁位置，每箱一次，服务端抽奖 |
| `buy_hearts` | 自然恢复后仍未满心且余额足够才扣费 |
| `buy_freeze` | 护盾未满且余额足够 |
| `makeup` | 有可补的缺勤日、今天未活动且余额足够 |
| `purchase_cosmetic` | `item_id`；读取目录价格，不允许客户端定价，购买后装备 |
| `equip_cosmetic` | `item_id`；必须已拥有 |
| `set_daily_goal` | `daily_goal`、经济投影 `revision`；旧版本修改冲突，不覆盖新配置 |

未知字段和任意加 XP/宝石请求均拒绝。`GET /students/{id}/progress` 返回当前投影和任务进度，`GET /learning/shop` 返回目录。家长可在最近验证后读取本家庭进度，经济写入要求单一学生学习模式。

红心保持五颗上限、五分钟恢复一颗、350 宝石补满；普通课每次错误扣心，原数感练习免扣。无心时不能继续普通课，可进入复习回心；每日最多一颗，少于五题时需全部首答正确。回心补练可以使用未到期题或教材练习，但不会提前推进其 SRS。

当日目标奖励使用独立领取键：即使中途提高每日目标后再次跨线，也不重复发当天的 20 宝石。这是云端一次性奖励约束的明确实现，不回算或修改旧本地成绩和余额。日期按家庭时区，服务端结算时确定；申报用时不兑换奖励，见 [学习事件说明](cloud-learning-events.md)。

本节描述的是后端能力。前端 LearningClient、儿童页面和联赛入口的云端写入还需按后续任务接入，不能因账本存在就认定全部旧页面已迁移。
