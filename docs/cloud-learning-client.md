# 前端学习客户端与身份隔离

`apps/web/src/lib/learning/` 提供任务 5.4 的客户端基础。课程、复习及其他儿童入口仍需按任务 5.5/5.6 接入，不能将此基础设施视为整条云端学习流程已完成。

## local 与 cloud

`LearningClient<P>` 约定固定的学习范围、读取进度和释放生命周期。local 适配器在独立文件 `local.ts` 中引用原 v13 progress store，保留档案键、迁移与领域规则；`run` 可执行既有 store 操作。云端页面不导入此适配器或原权威 store。

`CloudLearningClient` 只接收服务端确认的孩子模式，固定 `context_id` 和 `student_id`。家长须先代入孩子，管理员及家长管理模式不能创建学习客户端。孩子模式不公开原家长/家庭标识，因此缓存以服务端生成的登录上下文加学生 ID 为范围；不自行拼凑身份。

cloud 使用独立、内存中的 `projection` 保存服务端进度和学习会话。投影按 revision 拒绝倒退；课程队列、反馈和奖励不通过本地 store 合并。React 输入、错误、播放等 UI 状态由当前上下文下的组件拥有，身份变化时整棵学习组件树重新挂载。投影不保存到 localStorage，也没有客户端发放 XP/宝石的操作。

## 请求与重试

读取接口包括进度、摘要、错题、变化游标和指定会话。写入覆盖开始、作答、反馈确认、草稿、提示、完成、经济动作和用时检查点。请求契约分别见学习会话、奖励和活动文档。

每次写入先由 `prepare(path, body, method)` 固定 JSON 字节、学生范围及 UUID 幂等键，然后 `retry(key)` 发送。便捷方法 `start`、`updateSession`、`economy` 等复用这一过程。网络失败后 UI 应读取 `projection.pending`，用原键重试，不能再次调用开始/作答方法而生成新键。相同键的并发重试共享一个请求；不自动循环重试。

发送前读取 `/auth/session`，确认当前 Cookie 仍属于原上下文及学生；实际业务请求另附 `X-CSF-Learning-Context` 防止检查后的切换竞态，服务端仍执行完整授权。客户端确认不能代替服务端校验。

网络失败和 5xx 可能发生在事务提交之后，因此保留原键和请求体。明确的 4xx 业务拒绝显示原错误并移除待提交项，409 不换键、不覆盖服务端。401、模式/上下文改变、学生归档等身份失效会清除整个客户端。服务端确认前不更新权威奖励。

待提交字节保存在当前标签页的 sessionStorage，便于同一登录上下文刷新恢复；不含 Cookie、密码或认证令牌。只恢复精确匹配的上下文及学生，其他上下文的云端队列会被清除。浏览器禁止存储或配额不足时降为内存队列，这时刷新不能恢复未确认请求，但当前页面仍可用原键重试。队列不提供离线出题或判分。

## 生命周期

`AccountGuard` 在学习模式下挂载 `LearningProvider`，统一管理客户端订阅。账号或学生变化、退出、共享标签页通知、会话撤销/停用、归档和身份复验失败时，清理投影及云端队列，取消活动请求；即使 transport 未遵守 AbortSignal，返回后仍检查实例状态，旧响应不能发布。

普通页面导航或刷新卸载保留原上下文的待提交字节。显式登录变化通知即使发生在学习组件卸载后，也清理当前标签页残留队列。清理只作用于 `csf-cloud-pending-v1:` 命名空间，不删除本地档案或备份。

`LearningSyncStatus` 显示未确认数量。后续课程组件需提供当前操作的原键重试按钮，并处理服务端 revision 冲突。会话状态仍由服务端固定版本的检查点恢复。

## 验证命令

```sh
npm run check:learning-client
npm run type-check
```

客户端专项覆盖忽略 abort 的延迟响应、同学生重新登录、兄弟姐妹切换、响应丢失后的刷新恢复和原键重试、并发点击去重、失效清理、业务冲突、乱序 revision 与受限存储。原档案检查同时验证 local 适配器仍调用原 store、释放后拒写。这些是客户端行为检查，不代替后续真实数据库/双设备和浏览器全流程验收。

### 公开目录的短时内存缓存

每个有效客户端可缓存课程目录30秒、商店配置5分钟，合并同路径并发读取并返回独立副本，最多12项。dispose清空，过期后重新获取、失败不沿用过期结果。该缓存不包含身份、学生课程配置/进度、会话题目、作答/奖励或任何权威写入；原身份校验和幂等恢复继续生效。
