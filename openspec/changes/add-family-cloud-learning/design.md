# Design

## Context

动机与阶段范围见 proposal.md。M0 的运行与资源验收已记录于 `docs/family-learning-m0-audit.md`。2026-11-01 已确认调整为管理员集中建号、关闭公开注册、三类身份统一登录；统一登录、公开注册关闭、管理员初始化与账号管理、独立学生登录及家长代入模式已完成本阶段实现和相关测试；云端课程、学习摘要、导入导出删除仍按任务清单推进。本设计同时描述这些尚未完成的目标，不能将设计内容当作完整交付。

## Goals / Non-Goals

**Goals:** 最小增量接入家庭身份和数据库，保证两个孩子与两个家庭隔离；通过可重试事件完成学习记录同步；旧版 ID、资源及儿童交互保持兼容；为未来知识点模型提供版本化题目身份。

**Non-Goals:** 本轮不创建统一知识图谱、测评模型、学习计划引擎或月报，不替换儿童视觉体系，不引入微服务，不把客户端导入摘要当作可信学习事件。不在 M1 引入公开注册、短信、社交登录、监护人邀请或在线新增管理员入口；昵称和预置头像优先，避免新增头像文件上传链路。

## Decisions

### 1. 保留前端，新增模块化单体

选择 Next.js 静态前端 + `/api/v1` 同源代理 + FastAPI + PostgreSQL。`apps/api/app/` 按 auth、admin、families、students、curriculum、content、learning、portability 分领域，各模块拥有路由、契约、服务和数据库访问；事务由业务服务统一控制。admin 负责账号与家庭关联管理，复用 auth 的密码及会话能力，不将管理员权限隐含加入所有家庭查询。

直接围绕现有 store 加同步补丁会把奖励、历史和权限耦合；全面重构会扩大上游合并成本。增加后端和小型访问接口最适合当前职责边界。SQLAlchemy 管理持久化，Alembic 管理迁移，pytest/httpx 验证 API；不引入 Redis、消息队列或独立 Node 判分服务。

### 2. 开源组件核对与认证选择

2026-11-01 已核对官方文档及项目 README，属于文档级 spike，尚未进行安装或接入验证：

| 候选 | 匹配及证据 | 选择与缺口 |
| --- | --- | --- |
| [FastAPI Users](https://github.com/fastapi-users/fastapi-users) | MIT；有注册登录、Cookie、数据库策略、SQLAlchemy 支持及示例；维护模式仍维护安全和依赖 | 复用用户管理、密码及数据库 Cookie 会话基础，通过应用适配层封装；家庭授权、孩子模式及再次验证自行实现，不依赖其增加新功能 |
| [FastAPI 官方认证示例](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/) | 展示 pwdlib/Argon2 和认证依赖，适合规则参考 | 不直接把示例 JWT 代码扩成完整账号系统；数据库会话更便于撤销和模式降权 |
| [SQLAlchemy](https://www.sqlalchemy.org/) / [Alembic](https://alembic.sqlalchemy.org/en/latest/) | 覆盖 ORM、事务与迁移；Alembic 明确面向 SQLAlchemy | 复用基础设施，家庭隔离和幂等约束由业务模型实现 |
| [Capacitor](https://capacitorjs.com/docs) | 可封装现有 Web 业务 | 留给 M4 与现有 WebView 做登录、Cookie、文件和网络验证后决定，不在 M1 重建 Android |

现有后端已经锁定依赖并验证家长认证的基本接入，许可记录见 `apps/api/dependency-licenses.json`；这不代表新增三类身份已通过验证。继续复用 FastAPI Users 的密码哈希和可撤销数据库策略。现有适配基于必填邮箱，学生独立账号不应强迫提供邮箱，也不生成虚假邮箱占位；实施前需以当前安装源码及最小验证确认用户名与可选邮箱的适配边界，结果登记在实施文档。统一登录与业务角色由应用适配层维护，不直接开放库的通用用户管理端点，也不因库自带 is_superuser 字段自动放行家庭业务。

### 3. 统一登录、账号管理与家庭访问

统一 `/login` 接收账号及密码，不让客户端选择或声明角色。账号具有服务端角色 admin、parent 或 student；登录成功返回允许公开的身份、当前模式、绑定学生及目标入口：管理员 `/admin`、家长 `/parent`、学生 `/learn`。角色决定可用能力，会话模式只可缩小权限。前端跳转和导航隐藏之外，API 对每个请求验证账号状态、角色、模式及资源范围；登录响应不能再强制所有角色必须有家长家庭资料。

默认采用唯一且大小写归一的登录名，管理员和家长可保留真实邮箱信息，学生无需邮箱。现有家长以原邮箱作为初始登录名，迁移不得造成重名或改变账号与家庭身份；具体字符、长度及冲突规则在 auth 契约中固定并测试。密码沿用成熟哈希库。关闭注册页面与公开注册 API；直接调用原 `/auth/register` 不得创建任何用户、家庭或会话。

部署通过显式初始化命令创建一个管理员，读取 `CSF_BOOTSTRAP_ADMIN_LOGIN` 和 `CSF_BOOTSTRAP_ADMIN_PASSWORD` 等本地配置，不提供硬编码默认密码。仅空缺管理员时执行创建；已有管理员时重复或并发执行不得重复创建、提升既有普通账号、复活停用账号或覆盖密码。缺少凭据时初始化明确失败且不产生半成品；普通服务启动不自动重置管理员。仅初始管理员首次登录限制为修改密码、退出和最小会话状态查询，改密后轮换令牌进入后台。普通家长与学生在创建或管理员重置密码后均不强制改密，直接进入本人获准入口；重置仍撤销全部旧会话。迁移 0006 清除已有普通账号的强制改密标记，不改密码哈希、账号状态或家庭关联，也不变更管理员标记；降级不推测并恢复旧标记。初始化配置、明文密码不写入公开文件、日志或管理列表。

管理员经最近密码验证，通过专用 admin API 创建家长账号及新家庭 owner，或将家长关联到明确的已有家庭；M1 每个家庭一个 owner，其余家长为 guardian，关联操作不得静默替换已有 owner。学生账号在创建时必须关联明确家庭下的一个学生档案，可以为已有档案开通账号，也可以在一个事务中创建档案和账号。每个学生最多一个登录账号，账号不能绑定多个学生；失败全部回滚。家长仍可创建本家庭学生档案及编辑资料，但无权创建登录账号或修改角色，账号开通由管理员完成。

后台建号输入账号后以短延迟调用管理员专用 `/admin/login-availability`，检查覆盖全部角色及停用账号，使用服务端归一值，返回仅可用性。请求取消及输入版本检查阻止旧响应覆盖新输入；失败显示重试，保存仍依赖服务端检查和数据库唯一约束，预查不代替事务约束。创建、重置和管理员首次改密共用密码确认组件，两次输入及修改后的匹配即时验证，使用可访问提示和原生表单有效性阻止不一致提交；提交函数再次比较，确认字段不发送到 API，保存后清理两处密码输入。

后台提供家长/学生账号列表、必要家庭及学生关联信息、停用和密码重置；不因此开放全站学习明细、导出或代登录能力。绑定已有学习历史的学生账号不迁移到其他学生或家庭；需要更换登录名或重置密码时保留原 user/student ID。管理员不能通过普通账号管理端点新增管理员或修改自己的角色；运行时不给管理员自动附加家庭成员身份。

采用数据库可撤销随机令牌、HTTPS HttpOnly、SameSite Cookie；写接口校验 CSRF/Origin，登录、密码验证及密码变更限流，不在 localStorage 保存凭据。停用账号或重置密码撤销该账号全部会话；停用家长同时撤销由该家长代入的孩子模式会话，不自动停用同家庭的独立学生账号。归档/删除学生即时禁止其独立账号登录及已有学习会话继续访问，归档保留账号与记录，删除需按隐私流程清理关联账号。服务端判断归档状态，不能依赖前端缓存。

保留家长代入孩子模式：当前家长会话降权至指定学生，共享 Cookie 的标签页一起受限，其他设备独立。恢复家长模式要求原家长密码及有效家庭关系，轮换会话与 CSRF；独立学生会话即使通过本人密码验证也不能恢复为家长。独立学生只能退出后由家长重新登录。管理及敏感操作默认使用最近 5 分钟验证，普通会话默认 7 天到期。请求授权分别解析为管理员专用范围、家长→家庭成员→学生范围、学生账号绑定或家长孩子模式→单一学生范围，混合凭据不能提高权限。

| 身份/模式 | 允许范围 | 禁止行为 |
| --- | --- | --- |
| admin | 专用后台的家长/学生账号管理、家庭关联 | 默认读取家庭学习明细、代登录或进入家长业务 |
| parent / parent | 本家庭档案、教材、记录与验证后的导入导出删除 | 管理其他家庭或创建账号/授予角色 |
| parent / child | 已降权绑定学生的学习操作 | 管理家庭、读取其他孩子、跳过家长密码恢复 |
| student / child | 账号绑定学生的学习操作 | 选择其他学生、管理家庭、通过本人密码升级为家长 |

### 4. 数据模型与约束

ID 使用服务端 UUID，家庭时区默认 Asia/Shanghai；事件同时保存发生时间与服务端接收时间。配置含 revision，修改带 If-Match，陈旧修改返回 409。

| 实体 | 关键字段与约束 |
| --- | --- |
| users / auth_sessions | 唯一归一登录名、可选真实邮箱、密码哈希、admin/parent/student 角色、启用状态、首次改密标记；user、到期撤销、mode、student、最近验证时间；角色与模式必须一致 |
| families / family_memberships | 时区；family+user 唯一、role，M1 一个 owner |
| students | family、昵称、预置头像、可选出生年月/学校/备注、地区、学段年级、学年学期、时长目标、archived_at、revision |
| student_accounts | user 唯一、student 唯一、family+student 复合外键；只有 student 角色可绑定，独立于家长成员关系和学生档案生命周期 |
| subjects / student_subjects | 稳定字符串 code、显示元数据；student+subject 唯一、启用状态，不复用固定四科枚举作服务端业务边界 |
| textbooks / selections | 保留 legacy book ID、元数据及内容版本；学生+学科的生效区间、当前单元；无依据的 ISBN/年份可空 |
| question_versions | 稳定 question_uid + version 唯一；原 book、lesson、数字题号及内容角色映射；私有答案、解析、难度、原知识点标签、规则版本、内容哈希 |
| learning_sessions | student、来源、课程/阅读目标、固定题目版本集合、已确认检查点、状态、revision |
| answer_attempts | session、question_version、attempt 序号、答案、服务端结果、用时、发生/接收时间、来源、幂等键；不会覆盖历史 |
| learning_events / reward_ledger | student、事件种类、关联会话、服务端序号；一次性奖励业务键唯一，余额操作与事件处于同一事务 |
| progress / mistake_items | 由事件重建的投影；错题按 student+question_uid 去重，链接全部作答和复习历史 |
| legacy_imports / legacy_summaries | student、来源哈希、幂等批次、映射结果、不可追溯摘要，不生成历史作答 |

涉及学生的记录携带 family_id 和 student_id，以复合外键约束一致性；访问层强制按角色及绑定关系过滤，跨租户自动化测试覆盖读取和写入。独立学生不加入 family_memberships 以免获得家长权限，授权检查同时校验 student_accounts 的绑定、账号状态与学生归档状态。旧家长用户迁移为 parent，保留成员及学生 UUID；既有会话在角色模型升级时统一撤销并要求重新登录，迁移不得猜测旧 is_superuser 即为初始管理员。题号以所属内容定位，不假定原数字题号全局唯一。M2 增加统一知识点 ID 和多对多关系，M1 只保留原标签及章节引用。

### 5. API 与前端接入

| API 草案 | 行为 |
| --- | --- |
| POST `/auth/register` | 关闭公开建号，直接请求也不能产生用户/家庭/会话 |
| POST `/auth/login`, `/auth/logout`, `/auth/reauth`, `/auth/change-password` | 统一登录、撤销、按当前主体验证及修改密码；初始管理员改密前仅允许改密、退出及最小会话查询 |
| GET `/auth/session`, GET/PATCH `/me` | 返回最小身份、角色/模式、改密要求和目标入口；本人资料按角色提供，不能暴露其他家庭 |
| GET/POST `/admin/parents`, GET/POST `/admin/students` | 最近验证的管理员列出或原子创建账号及明确家庭/学生关联；不接受任意管理员角色 |
| GET `/admin/login-availability?login_name=...` | 最近验证的管理员检查账号全局可用性，不公开普通用户查重接口 |
| POST `/admin/users/{id}/disable`, `/admin/users/{id}/reset-password` | 仅管理普通账号，停用/重置时撤销全部旧会话，普通账号重置后直接登录 |
| GET `/family`, GET/POST `/students` | 家庭和孩子列表；写入需家长验证 |
| GET/PATCH/DELETE `/students/{id}`, POST `/{id}/archive` | 编辑归档、删除；DELETE 路径统一从 `/students` 起算 |
| POST `/mode/child`, `/mode/parent` | 仅家长主体代入本家庭孩子或验证原家长密码恢复；独立学生不可升级 |
| GET `/subjects`, `/textbooks` | 配置目录及有依据的推荐；无推荐则手动选书 |
| GET/PUT `/students/{id}/curriculum` | 学科开关、教材及当前章节；版本检查 |
| POST `/students/{id}/learning-sessions` | 创建课程、复习、跳级、故事等会话，固定内容版本 |
| GET `/learning-sessions/{id}`, POST `/{id}/attempts`, `/{id}/complete` | 无答案题目、幂等提交、服务端结算与检查点恢复 |
| POST `/students/{id}/events`, `/students/{id}/rewards/claims` | 阅读与时间检查点、任务/宝箱等已定义动作；不接受任意 XP、余额或事件类型 |
| GET `/students/{id}/progress`, `/mistakes`, `/changes?after=...` | 同步摘要、复习数据、学生内单调游标；这些相对路径均归属该学生 |
| POST `/students/{id}/imports/preview`, `/imports/confirm` | 预览与原子导入；确认使用预览 ID、来源哈希和目标 revision |
| GET `/family/export`, DELETE `/account` | 敏感操作验证、家庭范围导出删除 |

生成 OpenAPI 与前端 DTO；错误统一 `{code, message, request_id}`，401 未认证、403 模式受限、404 不可访问资源、409 幂等或版本冲突、422 校验、429 限流。所有学生路径再次校验授权，游标也绑定学生。

前端新增 `lib/api/`、学生上下文和 `/login`、`/admin`、`/parent`、`/learn` 入口及首次改密页；统一登录根据服务端角色与模式导航，直达页面也需重新校验会话，不提供公开注册入口。管理员后台含家长/学生账号列表、创建与家庭/档案关联、停用确认和重置密码；家长页保留家庭档案管理；学生 `/learn` 复用现有儿童学习组件和导航，不能显示家长或管理员管理入口。`/learn` 是学习首页，既有课时、复习等 URL 保留并统一校验学习身份。管理员首次改密、共享标签页降权、独立学生退出换账号、停用或会话撤销均有明确提示。

默认 cloud 页面树在根部统一校验会话，首页与旧课程/复习/商店等 URL 均不再挂载本地免登录界面：未登录跳登录，有会话按身份导航，服务故障阻断并提示重试。只有启动或构建时显式设置 `NEXT_PUBLIC_APP_MODE=local` 才启用原本地流程；云端入口不初始化本地档案和原 service worker。此入口保护不代表任务 4.2 的私有内容与构建资源隔离已完成。

使用 `LearningClient` 的 local/cloud 实现连接已有组件。先覆盖所有写入口，再启用云端模式。`LessonRunner` 继续管理动画、队列和输入，等待服务端结果后更新检查点；不得先用本地判分结算再覆盖。store 缓存以 user/family/student 为键，退出、切换和删除时清理并取消旧请求，旧响应必须验证上下文后才写界面。角色登录只适用于 cloud 目标，local 目标保留原本地档案流程。

### 6. 判分、答案保护与同步

Python 服务端按题型移植现有规则，先建立 TS/Python 共用向量，包括全半角、大小写、选项内容、分数、小数、单位、排序、连线、空值与非法输入。修复 parseFloat 前缀接受问题，以新的 grading_rule_version 记录；不覆盖旧完成成绩。奖励、SRS、阅读和日期语义也使用已有黄金向量或补充对照，不产生第二套含义。

云端构建不能将私有 Lesson 传入页面 props；课程、故事测验、跳级、复习和数感 DTO 均无答案和提前解析。扫描 JSON、HTML、RSC、JS、source map、音频索引及解释音频链接。答案和解释音频在提交后通过授权端点返回；已公开媒体中的可见答案也须列入资源核对。该保证针对新云端发布，无法收回他人已下载的旧开源内容。

每次操作在客户端产生稳定 UUID，服务端按学生+操作类型+幂等键约束唯一，并保存请求摘要和原始响应。相同键不同请求 409；作答、事件、奖励和投影同事务提交，必要时锁定学生余额。不同会话可并存，不用“最后一个 store JSON”覆盖。配置乐观并发，学习事件追加，已完成课程投影按既有最佳成绩语义归并。

网络失败保留已绑定身份与会话的待提交记录并显示未同步，原键重试；不提供完整离线出题或离线判分。服务端确认前不发奖。学习时间上报有检查点、上限与去重，明确不能证明人在屏幕前；同一学生重叠会话的每日用时按时间区间并集去重。记录服务器接收时间用于异常识别，家庭时区决定日/周归属。

### 7. 迁移与隐私

旧 localStorage 分档案导出，家长预览映射到指定云端学生，确认时使用 revision 防止覆盖并发新记录；仅补充历史摘要与不冲突进度，冲突保留双方并标注来源。不上传本地题目答案作为权威题库，不导入旧余额作为可消费新余额，不因导入触发奖励。旧装扮以 legacy 权益标记保留展示，与云端新奖励账本分离。未知内容留在导入报告中，不按名称猜题。

导出排除凭据和其他家庭数据，可包含本家庭学生账号的非敏感关联信息；管理员建号权限不等于家庭导出权限。删除经过范围预览和家长再次验证，清理活动数据库记录、关联学生登录账号、会话、服务端导出临时文件与客户端缓存；家庭整体删除仅限 owner，guardian 不得触发连带删除。独立学生不能删除家庭或自助修改归属。停用不是数据删除，不重置已有学生记录。M1 自托管默认不自动建立外部备份，若运营者启用备份必须配置保留天数并在删除前显示。恢复备份后必须重放删除清单再开放访问，清单到最后相关备份到期后删除；不得永久保留可识别的学生资料。

## Risks / Trade-offs

- [M0 未跑通] → tasks 第一组记录资源、启动、媒体与测试证据，未解决的阻塞禁止进入后续业务改造。
- [跨语言规则漂移] → 固定题目/规则版本、共用向量与差异报告；不为复用 TS 新建独立微服务。
- [改造 store 范围大] → 按访问接口渐进替换，保留 local 构建和原课程回归；云端不能漏接某个发奖入口。
- [静态答案泄露] → 云端资源独立目录、构建扫描、清理旧资源和 CDN/service worker 缓存。
- [子模式绕过] → 模式存于服务端会话，不依赖前端隐藏按钮；共享标签页同步降权。
- [角色或首次改密绕过] → 每次请求校验角色、模式、账号状态和改密限制，直接 API 与前端导航使用同一授权规则，独立学生密码不能恢复家长身份。
- [初始化覆盖管理员] → 显式命令、并发保护、无默认密码及重复执行不改密；不将日常启动或公开接口作为建管理员入口。
- [教材版权及质量] → MIT 只覆盖代码；登记素材来源、资源许可和教师审核状态，未确认授权资源不随新产品公开分发。不是法律合规结论。
- [组件维护模式] → FastAPI Users 仅通过 auth 适配层访问，版本锁定与升级测试，家庭业务不依赖库内部模型细节。
- [设备提交时间不可信] → 保留客户端声明与服务器时间，约束时长，不把时长作为真实专注度证明。

## Migration Plan

M0 已完成，后端已有基础迁移、家长认证、学生与教材配置。已验证用户名认证适配并新增角色和学生账号关联迁移；保留旧家长、家庭、学生及教材 ID，撤销旧会话，关闭公开注册，显式初始化管理员。原先的公开注册测试已替换为公开注册拒绝与管理员建号测试；三类主体认证、孩子模式、迁移与后台已分批验收，任务勾选按实际范围登记，家庭导出和学习明细仍需后续授权验收。接下来继续私有题库与学习接入；对管理员和两个家庭、每家两个孩子的独立账号及家长代入会话验证权限。使用同一内容版本建立题库及公开目录，先在独立测试部署启用 cloud 模式，完成本地档案预览迁移和两设备流程后才切换正式入口。

上线前备份活动数据库，确认数据恢复和删除清单机制，清理旧公开答案目录与缓存，配置 HTTPS 同源代理。回滚优先回滚前端/API 到兼容版本、停止新写入并保留已产生事件；不得自动执行破坏性数据库降级或回到公开答案目录。local 构建作为独立的原项目运行目标，不与云端账户数据混合写入。
